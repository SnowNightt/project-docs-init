# 文档维护规则

## 职责与事实来源

- README：项目用途、环境、启动和构建说明。
- AGENTS：Agent 的执行规则，只引用详细规范，不复制其内容。
- 工程文档：本目录记录文档导航、开发流程、测试、项目约定与当前架构。架构中区分目标设计和已实现事实，不重复定义功能约定。
- OpenSpec：功能规格与变更的唯一事实来源。[当前规格](../openspec/specs/)位于 `openspec/specs/<domain>/spec.md`；[进行中变更](../openspec/changes/)位于 `openspec/changes/<change-name>/`，归档变更位于 `openspec/changes/archive/`。变更中使用 OpenSpec 的提案、设计、任务和增量规格，不在 `docs/` 下另建一套。

实现细节以源码为准，预期行为以 OpenSpec 当前规格及相关变更中已确认的要求为准。两者冲突时先说明差异，不把代码现状直接视为需求。

## 更新矩阵

| 改动 | 检查并同步的文档 |
| --- | --- |
| 环境要求、启动、打包命令 | README |
| 目录、命名、代码归属规则 | 项目规范 |
| 模块边界、数据流、存储和通信 | 架构；本次技术设计放在 OpenSpec 变更的 `design.md` |
| 用户可见行为和业务规则 | 使用 OpenSpec 变更文档，按其流程同步当前规格；不在 `docs/` 下重复记录 |
| 测试组织、命令和验证要求 | 测试指南 |
| Agent 工作规则与文档流程 | AGENTS、开发流程、本文 |

OpenSpec 的文件命名、变更状态、同步和归档以项目实际安装的版本及配置为准。项目级文档只提供入口与工程约定，不另行规定功能 Spec 的状态或提案适用范围。用户对具体变化的明确要求无需重复批准；笼统授权或未回复不代表同意。

## 文件与链接约定

- 文件名使用小写英文和连字符，新文档必须从文档地图或已登记文档可达。
- 仓库内文件使用 Markdown 相对链接；不使用本机绝对路径。路径含空格时使用尖括号。
- 草案应明确标记，不把计划或尚未实现的能力写成当前事实。
- 修改时同步相关代码、测试和文档，并在同一个本地 commit 提交；不夹带无关改动。
